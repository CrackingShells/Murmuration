## S-w08-explorer-w08-f-1
Effort in an agent file did nothing when the agent ran as the main thread of a `-p` session, and worked as a subagent. Frontmatter low, medium, high, max as `--agent` main thread gave 550, 548, 538, 559 thinking tokens (default 566); the `--effort` flag on the same file gave 526, 527, 683, 2,457; as a subagent, 467 (low), 501 (default), 613 (high), 2,711 (max). The documentation says the field applies "when this subagent is active" and does not say the main-thread case is excluded; the documentation lists other fields that plugin agents ignore (permissionMode, hooks, mcpServers) and effort is not among them. I do not know whether the interactive main-thread agent (the PI) behaves the same or whether only `-p` ignores it. The lab's PI file has no effort field, so it matters for any future tuning of the PI.

## S-w08-explorer-w08-f-2
The default effort of a Sonnet 5.5 agent looks like low or medium, not high, though the user-level settings file holds `effortLevel: high`: default main thread 566 thinking tokens, low 526, medium 527, high 683. The documentation says models after Opus 5.5 ignore that key and start at their own default; I see it in behaviour but no log line names the effective level, and the debug log has no effort entry other than the invalid-value warning. If workers run at the model default, "effort low" may save nothing: on task B low had 0 thinking tokens in three runs and saved USD 0.003 a run, on task A nothing. A hard-claim probe is where a difference could show up.
refs: `__reports__/wave-08/explorer-w08-f/think_cli_effort.txt`, `verifier_A_subagent.txt`, `verifier_B_subagent.txt`; `/private/tmp/murmuration-w08/explorer-w08-f/runs/dbg-low.debug.log`.

## S-w08-explorer-w08-f-4
The signature-to-thinking-tokens fit has a large intercept (about 806 characters) and the lab's signatures are mostly small (median 1,684 characters, 4 turns below the intercept). Explorer-w08-a fitted 0.29 tokens per character on signature plus text; mine, from the platform count, is 0.33 per character beyond 806. The two agree on the mean (0.84x) but not per block: a 1,000-character signature is about 64 tokens by mine and 290 by the first. Which is right for short blocks matters for the many small turns of a worker; the fit is on 162 requests, 856 to 6,560 characters, all from short tasks, and the lab's longest signature is 102,684 characters. A direct test would be a worker-shaped run (long context, tool-heavy) with the stream open, then the same fit on it.
refs: `__reports__/wave-08/explorer-w08-f/sig_fit.tsv`, `sig_fit.txt`, `apply_sigfit_to_w08a.txt`.
