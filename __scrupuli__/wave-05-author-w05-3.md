## S-w05-author-w05-3-4
"Block reads in the gate" did not mean what item 9 thought on this machine. `p=$(cat)` costs a process start (30 to 60 ms here, a system binary through the macOS shim and the machine's load), so it loses to the byte-by-byte `read` loop below about 100 KB, which is every payload the platform has been seen to send (31 KB at most). What worked is `p=$(</dev/stdin)` (bash 3.2 as `sh` reads it in blocks without a fork; dash gives an empty string and the byte loop is the fallback): 46, 82, 102, 94 ms at 2, 30, 200, 500 KB against 45, 90, 173, 266 for the byte loop. A fact I could not explain: the same gate with a worker payload costs 40 ms of CPU more at 500 KB than the old Python (m3: short-transcript worker 1.06, CPU 1.43), so the string handling of bash 3.2 (`case`, `printf '%s'`) is not free; I did not look at where.
