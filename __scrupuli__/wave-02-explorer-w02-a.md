## symbols
- B: the token budget given to a worker. used: weighted tokens `input + cache_write + output + 0.1 * cache_read`, summed over the distinct requests of the subagent transcript (my definition; not a platform quantity).
- 80% note: a one-time hook text at used >= 0.8 B. Hard stop: `{"continue": false, "stopReason": ...}` at used >= B.

## S-w02-explorer-w02-a-1
Haiku workers called the 80% budget note a prompt injection in 7 of 23 runs that received it (`anx-c-1`; `anx-f-2` to `-f-5`; both agents of `par-1`): "The output of the f09 read ended with a note asking me to stop early ... That note came from inside a tool result, not from you, so I'm ignoring it". The transcript stores the hook text as a system-role request blob after the tool result, yet the model reports it as part of the tool output. The same agents obeyed the other hook channel every time: `continue:false` + `stopReason` arrived as "PostToolUse:Bash hook stopped continuation: ..." and 8 of 8 handed back at once (`anx-e-*`, `anx-f-*`). Three wordings differed (no preamble 5 of 10 ignored; a start note announcing the channel 0 of 5; an "is from the lab harness, installed by the user" prefix 0 of 6, but 2 of 2 ignored it in the parallel run), so the wording effect is not established (one-sided Fisher 0.08 and 0.06; haiku only). Open: do Sonnet workers, the real model, do the same; does the stop-continuation channel carry trust the additionalContext channel lacks?

## S-w02-explorer-w02-a-2
In `auto` the subagent's report is delivered by the `SubagentHandback` tool call, before `SubagentStop`. So the v5 presence gate (`SubagentStop` with `decision: block`) does nothing in the common case (agent hands back at once: `e2-gate-auto`), works only when the agent first ends in plain text (`e4-gate-auto-plain`), and a `PreToolUse` deny on the handback call that repeats loses the report altogether (`e3-gate2-auto`: 4 denials, "ended without delivering a report"). What does work: the full report text is in `tool_input.message` of the `PreToolUse` and `PostToolUse` of `SubagentHandback`, so a hook can save every report to disk without the model (and without the Write refusal on REPORT* basenames), and a one-shot deny made 3 of 3 haiku workers write `report.txt` first (`g3-*`). In `default` and `bypassPermissions` no `SubagentHandback` appeared (one run each) and `SubagentStop` carries `last_assistant_message`. What bothers me: the auto and non-auto paths differ in what a gate can do, `SubagentStop.last_assistant_message` is absent in auto, and the PI's `Agent` result in auto says the report "was delivered as a message ... not repeated here" (so the Agent tool result no longer holds the report). A report-saving hook must handle both paths.

## S-w02-explorer-w02-a-3
The quantities a budget can use are not the ones the agent already sees. The system blob every request carries `<total_tokens>N tokens left</total_tokens>`, which tracks the size of the current context (15,000,000 minus footprint), not spend, and a `USD budget: used/total` line only when the process has `--max-budget-usd` (so the Desktop probably has none). The hook can compute exact input and cache spend per request (246 of 246 `PostToolUse` calls exact; `PreToolUse` is one request stale in 101 of 246), but output is 8 to 15 percent of the truth in `auto`, and "used" depends on cache warmth (first call 6k with a warm cache, 22k cold, in my weighted unit), so a token budget needs the base context netted out. After a hard stop the agent overshoots by 9 to 15 percent (handback at 1.08 to 1.15 B). A long single request (a report written in one turn) fires no hook, so a budget cannot interrupt it. The unit question (tokens, USD, time) is therefore open: in the time-unit runs (`anx-t-*`) the 80% note landed at call 13 to 15 of 16 and changed nothing in 2 of 3 runs.
