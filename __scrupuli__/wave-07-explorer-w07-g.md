## S-w07-explorer-w07-g-1
Two sessions with the same command line differ by a factor of two in the classifier wait: arm B median wait to dispatch 528 ms (B0) against 1,015 ms (B1); L0 581 against L1 909 ms; arm A 530 (A1) against 942 (trial). The load average does not order them (B0 load 4.0, B1 3.5). Within a session the wait is stable (L1: 904-1,175 early, 738-941 late), so the level is set per session, not per call. What sets it: the server's load at that minute, the classifier model chosen per session, or something in the session start? This noise is larger than the lab plugin's hooks, so no experiment on hook cost can use auto mode wall time without many more sessions per arm.

## S-w07-explorer-w07-g-3
Most worker Bash calls cannot be helped by allow rules: of 1,869 single-call classifier-decided turns with small results, 1,623 run a program (python, uv, heredoc, sleep), and only 3 are bare `ls`/`cat`-type commands (`worker_command_shape.md`). The floor of a worker's Bash call is about 1.0 s (bare commands 1.02 s, grep/sed 0.99 s) and a program call has a median 1.72 s and p90 51 s, so the program's own run time and the classifier wait are not split in the records. If the user's permission layer were ever to take allow rules for `python3 -I <lab script>`, the saving per call is the classifier's 0.63 s; I have no measure of how many of the 1,623 are of the lab's own scripts, and none of how a rule for an interpreter is treated in auto mode (wave 5 CITED `Bash(python3 -c pass)` exact-match only; the docs say wildcarded interpreter rules are dropped on entering auto mode).
