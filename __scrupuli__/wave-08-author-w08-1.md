## S-w08-author-w08-1-4
Reading the Python for what a byte-equal port must copy turned up four things that look like nothing and are not: (a) `sum()` in Python 3.12 is a compensated (Neumaier) sum, so `used` differs in the last digit from a plain loop; (b) `sum([])` is the int `0`, so a transcript with no priced request gives `"base": 0` in the state file and `"used": 0` in the log where a float would print `0.0`; (c) `datetime.fromisoformat` accepts forms (a bare date, `20261019`) that make an int timestamp valid; (d) `scan` stops at the first user record for the brief and skips the `origin` branch for that line. None of these is documented in `budget.py`. The replay found only one gap after the build (a state file holding the JSON `null` is "no state" in Python; a first version failed such events) and one over-eager type check (`tool_input` read for events that never read it), both fixed.
refs: `rust/src/hook.rs` (`sum`, `Num`), `rust/src/budget.rs` (`scan`, `load_state`, `Loaded`), `__reports__/wave-08/author-w08-1/replay_exact_diffs.txt` (empty after the fixes)

## S-w08-author-w08-1-5

In the exact replay 587 of 3,821 events were handed to Python by the binary (566 of 1,200 fuzz events, 9 of 38 malformed, 7 and 5 in two synthetic groups, 0 of the 2,250 events built on 150 real transcripts). In the real-clock pass the counter is not available (the counting is in the test build only), so that pass cannot say how many it handed over. The hand-off adds one Python start to the event that needs it, so a platform that sent floats where it sends integers today would lose the saving without any visible change.

## S-w08-author-w08-1-7
The crate was `#![forbid(unsafe_code)]`; it is now `#![deny(unsafe_code)]` with one `#[allow(unsafe_code)]` function (`hook::local_offset`, a call to the C library's `localtime_r`) because the log's `t` field is local time with the zone's offset and std has no way to ask for it. No one has said whether this trade is acceptable for the guard's binary.

## S-w08-author-w08-1-9
