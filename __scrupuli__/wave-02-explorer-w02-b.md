## S-w02-explorer-w02-b-1
The skill listing is re-sent to every running agent at about the same second (clusters of up to 5 agents in 154 clusters over 248 listings in this run's transcripts), roughly once a minute while several agents run. The 2.1.302 binary shows the mechanism: the Desktop skills-sync routine (`skills_sync_round`) calls a function that marks skill names as "replaced" process-wide, and each agent drops those names from its "sent" set at its next turn and gets the listing again. What I could not show: why a sync round reports changes about every minute (nothing in the plugin causes it), and whether it happens outside the Desktop app. Headless runs of 12 to 38 s showed no re-send; two longer headless runs (long3, with and without CLAUDE_CODE_SYNC_SKILLS=1) were still running when I stopped. So the re-injection cost is probably Desktop-only, and a plugin cannot stop it except by giving workers no Skill tool.
refs: __reports__/reflective_run/w02/explorer-w02-b/ (sl.py, sl4.py, binfind.py); binary 2.1.302 offsets 221554541 (functions that mark and read replaced names), 224971605 (the per-agent filter), 230244489 (the sync routine that marks them)

## S-w02-explorer-w02-b-3
The platform's own subagent system prompt tells subagents not to write report, summary, findings or analysis .md files, apart from the hard Write refusal. Haiku obeyed that soft rule in 2 of 3 probes (w_pre2, w_rt wrote nothing, 0 Write calls, and said an "operator rule" forbade it) and ignored it in the third (w_pre1). Sonnet followed a brief that named the deliverable file in 2 of 2. So the soft layer is model- and brief-dependent; a brief that makes the report file the deliverable is what decided it, at n=2 for sonnet. Does the soft rule bite harder when the brief is long and the report file is one of ten things asked?
