## Correction and limits added after reproducer-w06-5's questions

- **Share estimate.** The 17.7 percent cited from w06-c7 pooled about 1,900 headless probe sessions; the lab's own sessions carry an unresolved expansion in 45.1 percent of 5,135 Bash calls (ESTIMATE, `__instrumenta__/w06c7_dollar_share.py`@next commit; reproducer-w06-5 got 45.5 percent on its own count). With 3 Bash rows the expected extra is about 0.45 x 3 = 1.35 guard starts per lab Bash call (about 50 ms at 38 ms a start), plus 1.1 s of hook time on the slowest `$` calls in this run's load. The h3 and h5 results are unchanged.
- **Heredoc bodies.** A bypass flag inside a heredoc body is not seen: the platform strips the body from the subcommand text an `if` rule matches, so `python3 - <<'EOF' ... --dangerously-skip-permissions ... EOF` and `bash <<'EOF' ... bypassPermissions ... EOF` ran the stub with no guard start (reproducer-w06-5, runs k01 and k02). It is the same stripping as for redirections. I had only the settings-file form (`d13` of w06-c7, which ran); the bypass-flag form is a let-through that this claim should have listed.
- **Out of the registered scope, not covered:** a settings JSON written outside `.claude/` (for example `out/s.json` with `defaultMode` bypass) and then passed by `claude --settings out/s.json`; a Write of a script with an extension not in the registered list (`.rb`, `.cjs`) or none (an extensionless launcher). The path rows name `.py .sh .bash .zsh .js .ts .mjs` and the three Claude settings paths only.
- **Title scope.** "Allows edits of the guard itself" means edits that add no bypass word. An Edit that adds a selftest line naming `--dangerously-skip-permissions` to the guard is denied by G4, and so is a `git commit -m` whose text names the flag (the Bash row `*dangerously-skip-permissions*` fires and the script sees it in a non-search command; the v0 mention-only denials). This is the registered rule working as designed, and it means the guard cannot be edited to add a test that spells the flag without the user's yes. The title overstates; the table above is the claim. A restated title would read: "...allows the three registered engineering edits (an unrelated line of `handback.py`, the guard's message, `handback.py` rewritten over itself)".
