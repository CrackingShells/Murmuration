## What would be different if the claim were false

If the platform ignored `tools:` for a main-thread agent, B's request 0 would equal A's. If the list lost a tool the PI needs, a smoke step would have no tool call, or a call would return "No such tool". I looked for both cases and made them happen on purpose in the haiku mechanics probes (`haiku_mechanics_probes.tsv`, n = 1 each, mechanics only): `tools: Read, Bash` leaves 2 tools and a 3,807-token request 0, and the PI then reports it has no echo tool; `tools: Read, Bash, mcp__*` does **not** keep the MCP tool `mcp__dummy__echo` (the bare wildcard matches nothing), while `mcp__dummy__*` keeps it. So the filter bites, and a plausible-looking list can lose tools without any error.

## The list, what it keeps and what it leaves out

Kept (43 entries): Agent, SendMessage, Skill, ToolSearch, AskUserQuestion, Read, Write, Edit, Glob, Grep, Bash, WebFetch, WebSearch, NotebookEdit, TodoWrite, TaskCreate, TaskGet, TaskList, TaskUpdate, TaskOutput, TaskStop, Monitor, ScheduleWakeup, ListAgents, EnterWorktree, ExitWorktree, EnterPlanMode, ExitPlanMode, CronCreate, CronDelete, CronList, PushNotification, SendUserFile, LSP, ListMcpResourcesTool, ReadMcpResourceTool, ReadMcpResourceDirTool, `mcp__WolframToolkit__*`, `mcp__plugin_colgrep-mcp_colgrep__*`, `mcp__arxiv__*`, `mcp__context7__*` (the four servers the worker files name), `mcp__ccd_turn__*` and `mcp__ccd_session__*` (the Desktop's plan and wrap-up boxes, chapters and hand-off, which the wave-4 PI called: update_plan 3 times, wrap_up once). Rule used: keep everything a PI of an open research project could use to lead a team, work with files and the web, wait, pace itself, ask the human, and show the human a plan; every deferred tool costs only its name per request, so those were kept freely. The loaded schemas were the cost, so those were cut by function.

Left out, with the reason:
- `Artifact`, `ArtifactComments`, `ArtifactData`, `DesignSync`, `PublishPlugin`, `ShareOnboardingGuide`, `RemoteTrigger`: publishing and sharing through claude.ai. The lab's human interface is markdown files in the lab; the Artifact tool's own text says it may publish "without being asked". `Artifact` alone is 55.4k to 59.6k characters, 74% of what the allowlist removes in the Desktop projection. One entry re-adds it.
- `Workflow`: its own text allows it only after the user opts into multi-agent orchestration at scale; the PI's team is dispatched with `Agent` and budgets.
- `ReportFindings`, `SuggestSkills`, `SearchPlugins`, `SuggestPluginInstall`, `ListPlugins`, `ListSkills`, `SearchSkills`: code-review UI, plugin and skill marketplace. The PI loads `research-loop` by name.
- Desktop MCP servers `Claude_Browser` (GUI browser automation, about 30k characters), `Claude_Code_iOS_Simulator`, `visualize`, the Claude Docs server (living docs), `terminal`, `scheduled-tasks` (duplicates `CronCreate`), `mcp-registry`, and the `ccd_*` administration servers (host, pr, settings, sidebar, view, window, session_mgmt, connectors, directory): the app's own control and GUI, not research. Web pages are read with WebFetch and WebSearch, which the PI keeps.
- **Not kept, and this is the real cost: any MCP server the plugin cannot name.** A user's connectors (in the Desktop wave-4 snapshot: a GitHub server and a file-storage server, both with uuid names, and macOS Calendar and Reminders) disappear from the PI under B, and so do MCP servers a given project attaches. `mcp__*` does not work as a catch-all (tested). The line is one line to edit, but the stated aim "a PI on any open research project keeps every tool it needs" is **not met for user-attached MCP servers** by an allowlist.
