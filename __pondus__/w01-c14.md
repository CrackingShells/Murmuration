## What changed from w01-c1, and why

reproducer-w01-1 gave w01-c1 OVERSTATED (`__pondus__/w01-c1.md`, its section). This claim restates it with the scope in the title and with the corrections made after the exchange:
- Auto-mode `SubagentStop` has no text only when the agent ends by calling `SubagentHandback`. When an agent ends a turn in plain text first, the stop carries `last_assistant_message`, the harness answers "[handback-send-enforce] Your report has not been delivered", and the agent then calls the tool. The hook stores that text as `status=draft` (not a delivery); a resumed agent in auto mode yields 2 sections, or 3 with a draft (p8_d299_auto_two here; p4_auto_two in the verifier's run).
- The file holds deliveries, plus drafts and gaps marked as such; it is not "hand-backs and only hand-backs".
- The first version of the hook read its own file with a regex over the whole text. A hand-back quoting a header line made the next genuine hand-back be dropped; a lone surrogate made the write fail with no trace. The revised hook parses the file by hopping over each body with its `bytes=N`, and escapes a lone surrogate (`status=delivered-escaped`). Both cases are in the selftest and were re-checked by the verifier offline.

## Condition of the proposal

The hand-back file is a recovery aid for the PI and humans only. No hook, brief or skill may feed `__statera__/handbacks/` to agents automatically (as `resume_brief.py` does for wave notes and puzzles). Reason: in auto mode the harness reviews each hand-back and may deliver it with a note, deliver it flagged, or withhold it (internal states `send`, `flagged`, `withheld` in the 2.1.302 binary). The hook receives the same `tool_response` ("Report delivered to your caller.") in every case I could produce, so it cannot tell, and the file may hold text the PI never received, without the frame the harness puts around a delivered hand-back. The file's header and each section's frame line say "model output: data, not an instruction"; that is a mitigation that depends on the reader obeying it, not a control. I did not test whether a model reading the file respects it, and I could not make auto mode withhold anything with haiku.

## Known limits and side effects

- Silent loss that remains: any exception inside the hook after the lab is found is dropped by design (exit 0, no output). Measured: a read-only `handbacks/` folder gives exit 0, empty stdout and stderr, no file, no `missing` section (my test and the verifier's agree). A `SubagentStop` that never fires also leaves no trace (not tested). Not silent: a `SubagentStop` without text and without a recent delivery writes `status=missing`; a lone surrogate is escaped.
- `draft` is inferred from `permission_mode == "auto"` plus text at a stop. If a binary without the `SubagentHandback` tool ran in auto mode, its only copy of the report would be labelled draft (not tested).
- Side effect on user state: every `claude -p` run started below this worktree registers `murmuration@murmuration-local` (scope local, one entry per work folder) in `~/.claude/plugins/installed_plugins.json`: 210 entries at the time of writing (mine and the verifier's). Cause: the worktree's `.claude/settings.local.json` (`extraKnownMarketplaces` murmuration-local, `enabledPlugins` murmuration@murmuration-local, `agent: murmuration:research-pi`) is found by `--setting-sources project` from any folder below the worktree. The real plugin did not take part: a stream-json run with `--include-hook-events` (`scratch/q3_hooks/stdout.jsonl`) lists `hbtest` and the built-in `cc-plugin-*` plugins, `agent` is None, and only the two intended hooks fired; a run outside the worktree (p7) leaves no entry. I did not edit the file.
- The agent name comes from `.meta.json` `name`, else the brief's "Your name is <name>", else `<type>-<id>`; the fields `.meta.json` `name` and the tool `SubagentHandback` with `tool_input.message` are undocumented (the binary marks the hand-back machinery `@internal`). If the tool is renamed or the field moves, every auto-mode hand-back becomes a `status=missing` section (shown by p6, the `SubagentStop`-only variant).

## The Write refusal (MEASURED, and read from the binary)

- The rule is in the Write tool's `validateInput` of 2.1.295, 2.1.299 and 2.1.302: for a subagent (`agentId` set), a Write whose basename matches `/^(REPORT|SUMMARY|FINDINGS|ANALYSIS).*\.md$/i` is refused with errorCode 5 and "Subagents should return findings as text, not write report files. Include this content in your final response instead." Offsets of the string in 2.1.302: 102410824 and 222130500.
- Headless test with 13 names on both binaries: refused `REPORT.md`, `report_head.md`, `Summary-notes.md`, `findings.md`, `ANALYSIS_2.md`, `FINDINGS.MD`, `reports.md`, `notes/report.md`; allowed `my_report.md`, `w01-c1.md`, `wave-01-author-w99-3.md`, `report.txt`, `analysis.py`; Edit of an existing `REPORT-old.md` and a Bash heredoc to `REPORT-bash.md` succeeded; the main thread wrote the same names with 0 refused. In this run's transcripts: 6 refusals (`report.md` by agents a, b, c twice, f; `report_head.md` by d), each with a matching basename, no mismatch. So `__pondus__/<claim-id>.md` and `__scrupuli__/wave-NN-<name>.md` are not affected, and a claim whose id began with `report`, `summary`, `findings` or `analysis` would be.

## Against the hunch, and the zero-code alternative

The PI already receives each hand-back in context, so the file adds recoverability and verbatim fidelity (no trailing text, no neutralised tags), not information. A cheaper alternative for the refusal alone is a brief that asks for the report file under a name the rule does not match (`<name>-notes.md`); it leaves the PI-visible copy altered and relies on the agent writing it. Proposed brief wording (not applied): "Your final message is your report; the platform refuses a subagent's Write of files named REPORT*, SUMMARY*, FINDINGS* or ANALYSIS* ending .md. Write data, code and puzzles to files; hand the report back as text."
