**The change.** `bin/manifest.json` (written by `python3 -I scripts/build_manifest.py`): sha256 of each `bin/<target>/murmuration`, of `scripts/permission_guard.py`, of each Rust source (`rust/Cargo.toml`, `Cargo.lock`, `gen_tables.py`, `src/*.rs`) and one hash over those. `install_binary.py` installs the binary only if (a) its hash equals the manifest's, (b) the guard and the Rust sources hash to the manifest's values, and (c) a copy of it, run on 12 fixed payloads (allow, G1 x2, G2, G3 x2, G4, allow-write, mention-only allow, three malformed), gives the same exit code and stdout as `permission_guard.py` run by the hook's own interpreter. Otherwise it installs the `#!/bin/sh` launcher for `permission_guard.py`, removes the stamp, and prints a SessionStart `additionalContext` note and the same line on stderr (exit 0). A stamp next to the binary lets a current install skip the self-test; hashes are recomputed every start. The copy is atomic (temporary file, self-test on it, rename), so a verified file keeps its inode. The pre-commit file now rebuilds the manifest; the CI file has a `manifest` job that gathers every target's binary and writes it. Neither is installed or pushed. The binaries are unchanged (built at 029bdea); only the manifest is new.

## Results

**h1 (each doubt falls back, visibly) — passes, 4 of 4; MEASURED.** Each fault in its own scratch tree and data folder; in all four the installed file is the launcher, exit 0, the notice is on stdout as `additionalContext` and on stderr, and it names the cause:

| fault | cause named in the notice |
|:--|:--|
| `permission_guard.py` edited after the build (its denial text changed) | `scripts/permission_guard.py changed since the binaries were built` |
| a Rust source edited after the build | `the Rust sources changed since the binaries were built` |
| one byte flipped in the middle of the binary | `the binary bin/<target>/murmuration does not match its hash in bin/manifest.json` |
| a stub that allows everything, with the manifest rebuilt so only the self-test can catch it | `the binary's decision differs from permission_guard.py on the self-test payload <name>` |
| (extra) `bin/manifest.json` missing | `bin/manifest.json cannot be read (...)` |

Then the registered and malformed cases (121 + 4) and 300 + 60 fuzz events through the installed launcher equal the tree's own `permission_guard.py` in all five (0 events differ). That last check is close to tautological after a fallback, since the launcher is the Python guard (S-w07-author-w07-5-9); the evidence that carries h1 is the launcher, the notice and the named cause, and h4.

**h2 (the clean case) — passes; MEASURED.** Unmodified tree, arm64: installed the binary (hash equals the manifest's, stamp present), no notice, stdout and stderr empty, decisions equal on the same sets (0 differ), 1,042 ms cold on that run. x86_64 under Rosetta (`arch -x86_64 /usr/bin/python3`, Python 3.9.6): the installer picks the x86_64 target, the binary's hash equals the manifest's x86_64 entry, the self-test passes, installed the binary, no notice (3,340 ms cold). The x86_64 g1 quick run under Rosetta (`g1_quick_x86_64_rosetta.txt`): registered 121 events, 0 differ; malformed 4, 0; fuzz Bash 300, 0; fuzz Write 60, 0; the same 10 odd-type events and 1 stress event differ as for the aarch64 binary (w07-c6's reported-apart sets). Quick-sized and Rosetta only, not a real Intel machine.

**h3 (cost and races) — reported and passes; MEASURED.** Installer wall time per session start, whole process including the interpreter's start, 10 runs each, load 6.57: fresh data folder (copy, first exec of the new file, self-test of 12 payloads twice) median 853 ms (min 807, max 887); warm (binary and stamp current, all hashes recomputed) median 38 ms (min 37, max 39); fallback to the launcher median 38 ms; `python3 -S -I -c pass` 22 ms. Concurrency: 3 rounds of 12 installers started together against one fresh data folder, with the installed file run on 4 payloads over and over meanwhile: 36 installers, 0 failed or noisy; 244 guard runs, 0 wrong or failed; the final binary's hash equals the manifest's; 0 leftover temporary files.

**h4 (live) — passes; MEASURED, 2 sessions.** Faulty export (`permission_guard.py` edited after the build so that its denial text reads `permission_guard-EDITED`): the SessionStart output carried the notice, the model quoted it verbatim when asked, `echo h4-ok` ran, and the redirect into `.claude/settings.json` was denied with `PreToolUse:Bash hook error: permission_guard-EDITED (G3): ...`, so the launcher (the edited Python guard) decided; the installed file starts with `#!`. Clean export: the model reported `NO NOTICE`, `echo h4-ok` ran, the same redirect was denied with `permission_guard (G3): ...`, and the installed file is a Mach-O binary. Details: `h4_live.md`.

## What it shows, and what it does not
- A tree whose guard, sources or binary changed after the build, or whose binary decides wrongly on 12 payloads, runs the Python guard and says so: the doubt resolves to the reference, visibly, not to a block of every call and not to a silent stale rule.
- The cold install costs about 0.85 s once per data folder and version (the self-test); every later start costs 38 ms.
- It does not show that a binary was built from the hashed sources, that it is right outside its 12 payloads, or that an installed marketplace copy carries `rust/` and `bin/manifest.json` and runs the installer before the first Bash call. The last is the landing step's smoke run.

## What this closes
It closes the question whether the installer can tie `bin/` to `rust/` and `scripts/permission_guard.py` and fall back visibly on any doubt, on this machine, for a `--plugin-dir` export and a scratch tree. Outside that scope: the installed-plugin path (open gap 3), Linux and Windows, and a build that is reproducible byte for byte.
