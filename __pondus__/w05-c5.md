## Results

### m1: output

16 784 bytes from main, from the new version with the cache off (one git call), cold, and warm: **byte-identical in all four** (`e8_identity.txt`), on the frozen tree. The selftest's own comparison (report with the cache and without it, cold and warm, after each change of a fixture file) is equal throughout.

### m2: wall time, ms (n = 30, interleaved; `e8_timing.md`)

| case | wall median | wall p90 | CPU median | against main |
|:--|--:|--:|--:|--:|
| main (4c675ec) | 1082.4 | 1110.7 | 888 | |
| one git call, no cache | 953.1 | 968.8 | 850 | -12% |
| one git call, cache cold (file removed, parse and write) | 1058.2 | 1074.3 | 940 | -2% |

The three `git worktree list` calls cost 125 ms in explorer-w05-d's measure; here the single call saves 129 ms. Explorer-w05-d's patched copies gave 830, 706 and 306 ms on this tree at a lighter load; the ratios agree (one call -15% there, cache -63%).

### m3: selftest

PASS at the tip; the eight mutants listed in the method each make it fail (checked once each; the file is restored after each). The other four selftests (budget, handback, resume_brief, user_words) pass at the tip.

### m4: lines added

`git diff 4c675ec HEAD --numstat -- scripts/lab_status.py`: 147 added, 8 removed, of which 64 are selftest lines and 83 are code and comments (`Cache`, `cache_path`, the `read_transcript` wrapper, the single call). `lab_status.py` is 1245 lines against 1106.

## Decision (E8, as pre-registered)

m1 identical: yes. m2 down by at least 40%: yes, 68% warm. m3 selftest passes: yes. **Proposed**, and it stays on the branch tip (b932690, 4eb2272). If only the single git call were kept, the rule's fallback (m1 identical and m2 down at all) is also met: -12%. What the 68% depends on: a warm cache. The first run after a cache is empty or its file is removed costs main's time plus 2% (the write), and a lab that has just got a new session pays for that session's files only (the biggest transcript in this tree parses in 27 ms). The cache file for this tree is 2.3 MB, in the lab's git-ignored `.harness/`.

## What this closes, and what it does not

Closes: whether `lab_status.py` can drop to a third of its time with its output unchanged: it can, on this machine and this frozen tree, by the cache; the single git call alone saves 12%. Outside that scope: a live tree under write (not measured), the cache on a machine whose clock or filesystem gives coarse modification times (a rewrite with the same size inside one time tick would be missed; the selftest tests the other three cases), and `resume_brief.py`, which imports `lab_status` and so pays its import at each resumed session (not changed).
