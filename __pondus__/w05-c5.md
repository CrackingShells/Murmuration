## Decision (E8, as pre-registered)

m1 identical: yes. m2 down by at least 40%: yes, 68% warm. m3 selftest passes: yes. **Proposed**, and it stays on the branch tip (b932690, 4eb2272). If only the single git call were kept, the rule's fallback (m1 identical and m2 down at all) is also met: -12%. What the 68% depends on: a warm cache. The first run after a cache is empty or its file is removed costs main's time plus 2% (the write), and a lab that has just got a new session pays for that session's files only (the biggest transcript in this tree parses in 27 ms). The cache file for this tree is 2.3 MB, in the lab's git-ignored `.harness/`.

## What this closes, and what it does not

Closes: whether `lab_status.py` can drop to a third of its time with its output unchanged: it can, on this machine and this frozen tree, by the cache; the single git call alone saves 12%. Outside that scope: a live tree under write (not measured), the cache on a machine whose clock or filesystem gives coarse modification times (a rewrite with the same size inside one time tick would be missed; the selftest tests the other three cases), and `resume_brief.py`, which imports `lab_status` and so pays its import at each resumed session (not changed).

**m3 (selftest).** `lab_status.py --selftest` passes at the tip. The author gives no mutant artifact (no file in the evidence list holds the eight mutants), so I wrote 14 of my own (`w05c5_repro_mutants.py`). Killed: size-only, mtime-only, ignore-version, cache-a-parse-that-warned, drop-R_OK, ids-as-text, no-gitignore, no-makedirs, always-trust (ignore stamp). **Survive (selftest still passes):** non-atomic write (tmp file then copy to the target), keep entries not seen in the run (no pruning), stamp taken after the parse instead of before (the stale-on-growth race), write when nothing changed, tmp name without the pid. **Probes the claim leaves out** (`w05c5_repro_stale_probe.py`, synthetic config dir, cached vs uncached output):
- Growth: appending to a transcript, twice, then re-running: SAME as uncached (size changes). Same size and same `st_mtime_ns` with other bytes: DIFFERENT (stale), the limitation the claim states.
- Corrupt cache: truncated at half, empty, binary junk: all ignored, output SAME, file replaced. **Valid JSON with a malformed entry that has the right stamp** (messages = 5; `[[1]]`; a message that is `7`; `{}`; usage null): `lab_status.py` crashes with a traceback, rc 1, five of five, where the uncached run prints the report. The cache is not rewritten on a crash, so every later run fails until the file is deleted. The claim says the file is "read with every error ignored"; only errors in opening and parsing the JSON are.
- Concurrent: 8 cold processes at once on one cache path: 8 of 8 outputs equal to uncached, cache valid JSON afterwards, no `.tmp` left.
- **A stale cache gives a wrong figure in one case that needs no clock tick.** `load_sessions` builds `owned[key] = dict(msg, ...)`, a shallow copy, so `merge_usage(have["usage"], ...)` writes into the dict that the cache holds, and `Cache.save()` (called after `load_sessions`) dumps the merged numbers. Fixture: message m1 in `s1.jsonl` (output 10) and a copy in `s2.jsonl` (output 5 000). Cold and warm runs agree with uncached; the cache file holds output 5 000 for `s1.jsonl`'s m1. Remove `s2.jsonl` (s1 untouched): cached prints 5 005 output tokens, uncached 15. On the real tree `copies = 0`, so it does not occur there; it needs a message id in two transcripts (a forked session, a copied agent file, the case `load_sessions` was written for) and then one of the two files changing or leaving the session list (a worktree removed from `git worktree list`).

**Decision against E8 as written.** m1 identical: yes. m2 down at least 40%: yes (-68.7%). m3 selftest passes: yes. The rule's two further conditions (cache allowed "only if its writes are atomic and it has a selftest"): atomic by construction, selftest exists. The decision "proposed" follows. The title gives -68% first and the cold run (-2%) and one call (-12%) in the parenthesis; the warm figure is the one the 40% test passed on, and it is the usual case only after a first run per lab and while few transcripts change: a new worktree or a deleted cache file starts cold, and the live session's own transcript is parsed at each run (27 ms for the largest here).
