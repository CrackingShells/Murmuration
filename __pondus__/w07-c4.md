## What failed or did not hold

- The protocol's ceiling of 0.155 s a call did not reproduce: the saving is 0.05-0.06 s a call (about 20 % of a warm call), 3x smaller. The 0.155 s was the difference of two medians under load 3-15; larger pair differences (0.14-0.18 s) occur only in the upper tail of the pairs. Time is therefore a small gain; the lab's 317 calls give about 16-19 s over its life [ESTIMATE: 317 x 0.05-0.06 s].
- The first version of B failed o3 in the first full run: (i) a folder that does not exist, below a repository, got the enclosing repository's list where git answers []; (ii) a bare repository below a repository got the enclosing list where git answers the bare repository. Cause: the upward search for `.git` did not stop at a missing directory or at a bare repository. Found because the first run's scratch folder lay inside a repository by accident; fixed (commit ddbdecf) and covered by five new cases. Order of the linked worktrees was also wrong in the first version (A sorts by path, case-insensitively on macOS); fixed in the same sweep, before any recorded run.
- Not covered, by construction: git's `safe.directory` and a global `core.ignorecase` (only the order would differ) are not read; the uid test stands for ownership. A git release that stops writing absolute `gitdir` paths is covered by the fallback only for the relative form (tested), not for other new formats. The cost-state exact figure hides change 2 for ended sessions (it applies to open sessions and to the per-agent list-price rows).
- Cost of the change: +91 net lines in a 1,316-line script, a second code path (the fallback) to keep in step with git; the saving is 0.05 s a call. Whether that is worth it is for the PI.
