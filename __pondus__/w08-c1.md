## What it shows, and what it does not
- On 3,821 replayed events the Rust subcommands write byte-identical records to the Python scripts' (log lines, state files, pending records, hand-back files) and print the same answers; the cost of an event outside the modeled shapes is one Python start (587 of 3,821 here, none on real transcripts).
- A doubt resolves to the Python scripts, with a named cause, on each of 11 faults (e2); a tree whose scripts or Rust sources changed after the build runs Python for the guard too.
- The saving per hook start is 7 to 12 ms (budget) and 8 to 15 ms (hand-back) wall and CPU outside the platform, about a third of the Python start at this load; in the platform it is 7 to 9 ms by session medians, with a control drift of the same order. It is not 41 ms (S-w08-author-w08-1-1).
- It does not show that the binary is right outside the replayed shapes (the installer's tests cannot show it), that a recorded platform payload is handled (none was available), or the worker path's saving in the platform.

## What this closes
It closes the question whether `budget` and `handback` can be subcommands of the same binary, installed by the same installer with the same fall-back to the Python scripts, making the scripts' decisions and writing their records, and what that saves per start on this machine. Outside that scope: Linux and Windows, a worker session in the platform, a marketplace-installed copy (open gap 3 of w07-c8), and the claim that wall time signs reach 95 percent per payload (they did in 11 of 14 runs).
