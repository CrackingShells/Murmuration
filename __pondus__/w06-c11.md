## How to read the k6 count

The limit of 55 was taken from the low end of v2's bracket, which counted only the G1-type denials of a gated guard; v3's unconditional row also sees what an `if` strips (`CLAUDE_CONFIG_DIR=` assignments, redirect writes), and those are the 59 extra denials. The sample of ten (random.Random(0)) printed in the results file reads: nine of them are probe runs that set `CLAUDE_CONFIG_DIR` or write a settings file in a scratch or decoy folder, or heredocs writing protocol text, and one is a probe that runs `claude -p` with a mode word; the tool truncates each call at 200 characters, so the file shows the head of each call only. Which of the 113 are legitimate lab work and which are the very act the guard is for is a judgment I did not make call by call; at least some of the G3 ones write the main repository's `.claude/settings.local.json` (a w05 explorer restored it from a backup), which is the file the user said must not be touched. This changes what the numbers mean, not the registered result: k6 as registered fails.

## What the passing metrics show

One unconditional Bash row costs exactly 1 guard start per Bash call (versus about 1.35 for v2's three rows at the lab's 45 percent expansion share) and denies at the Bash level what the `if` rows cannot see: the leading `CLAUDE_CONFIG_DIR=`, the redirect writes of settings files, and a heredoc that carries the bypass word with a `claude` call (k02). It does not stop what a text rule cannot see: a flag built from pieces, base64, a script already on disk or written by a path the rows do not name, a settings JSON at another path, and the word-count-neutral edit; reproducer-w06-5's live cases against the v2 build (k03, n01 to n04, g01) are not repeated here and are CITED in w06-c12.
