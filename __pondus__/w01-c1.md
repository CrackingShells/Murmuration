## 1. What the Write refusal covers (MEASURED, and read from the binary)

- The rule is in the Write tool's `validateInput`, in all three binaries present on this machine (2.1.295, 2.1.299, 2.1.302):
  `if (s.agentId && /^(REPORT|SUMMARY|FINDINGS|ANALYSIS).*\.md$/i.test(basename(path))) -> refuse, errorCode 5`, with the message "Subagents should return findings as text, not write report files. Include this content in your final response instead." and a telemetry event `tengu_subagent_md_report_blocked`.
  Read with: `grep -a -b -o -F "Subagents should return findings" <binary>`, then `dd if=<binary> bs=1 skip=<offset-1500> count=2300 | tr -c '[:print:]\n' '?'` (offsets 222130500 in 2.1.302, 203241456 in 2.1.299, 195168639 in 2.1.295).
- It applies only to the `Write` tool and only when the caller is a subagent (`agentId` set). It tests the basename only, so a directory does not help (`notes/report.md` is refused). It is anchored at the start of the basename and case-insensitive on the whole pattern, so `reports.md`, `report_head.md`, `Summary-notes.md`, `ANALYSIS_2.md` and `FINDINGS.MD` are refused and `my_report.md` is not.
- This run's subagent transcripts (`write_attempts.tsv`, made by `write_attempts.py`): 16 `Write` calls, 6 refused, 6 whose basename matches the regex; no mismatch. The refused files are `report.md` (agents a, b, c twice, f) and `report_head.md` (agent d). That is six refusals, not five: the wave note counts agents a, b, c, f; d's refusal was a different name, `report_head.md`. Every other file the agents wrote (scripts, csv, `run_all.sh`, `__scrupuli__/wave-01-<name>.md`) succeeded.
- Headless test, 13 `Write` names from a subagent (`results/write_sub_2.1.302.tsv`, `results/write_sub_2.1.299.tsv`, same result on both binaries): refused `REPORT.md`, `report_head.md`, `Summary-notes.md`, `findings.md`, `ANALYSIS_2.md`, `FINDINGS.MD`, `reports.md`, `notes/report.md`; allowed `my_report.md`, `w01-c1.md`, `wave-01-author-w99-3.md`, `report.txt`, `analysis.py`. `Edit` of an existing `REPORT-old.md` and a Bash `printf > REPORT-bash.md` succeeded. The same names written by the main thread (`results/write_main_2.1.302.tsv`): 0 refused.
- Hence `__pondus__/w01-c1.md` and `__scrupuli__/wave-NN-<name>.md` are not affected, and a claim file for a claim called `report` or `summary` would be. A shell heredoc is not covered, which is how explorers d and e wrote their reports.
- Side effect seen once (first attempt of the test, transcript kept under `~/.claude/projects/*author-w01-1-scratch-w1-sub-302-work/`): the haiku subagent stopped at the first refusal, did not make the other 14 calls, and handed back an apology. The message tells the agent to put the content in its final response, and it did.

## 2. The hook (MEASURED)

- Files: `plugin/scripts/handback.py` (177 lines: 69 executable, 25 of docstring, the rest selftest, comments and blanks; `python3 handback.py --selftest` passes) and 2 entries in `plugin/hooks/hooks.json` (27 lines): `SubagentStop` (no matcher) and `PostToolUse` with matcher `SubagentHandback`, both running the same script. No output, always exit 0, nothing blocks.
- Where the text sits (raw payloads in `scratch/*/RAWLOG`):
  - default and bypass mode: `SubagentStop.last_assistant_message`; `SubagentHandback` does not exist.
  - auto mode: `PostToolUse(SubagentHandback)` fires first, with `agent_id`, `agent_type`, `tool_input.message`, `tool_response {"success":true,"message":"Report delivered to your caller."}`; then `SubagentStop` without text.
- File: `__statera__/handbacks/wave-NN-<agent name>.md`, wave taken from the `-wNN-` in the name (`<name>.md` when there is none). Each hand-back is a section `## hand-back <n> | <iso time> | agent_id=<id> type=<agent type> event=<event> bytes=<N> sha256=<12 hex>`, a blank line, the text, a newline. Slicing by `bytes=N` is exact even when the text contains lines that look like headers. One `os.write` per section, so two agents never interleave.
- Agent name, in order: `<session>/subagents/agent-<id>.meta.json` field `name` (present in the real transcripts of this run, e.g. `author-w01-2`); else the brief's "Your name is <name>" read from the agent's transcript (this is the convention in `briefs.md`); else `<agent type>-<id>`. Both of the first two routes were hit live: p4_auto_two had `name: null` in the meta file (the model had left the parameter out) and still produced `wave-99-author-w99-1.md` from the brief; p5 had the name in the meta file.
- Duplicate guard: the same text twice in a row for one agent is written once. Gap guard: a `SubagentStop` with no text, with no section of that agent written in the last 30 s, writes a section `sha256=MISSING` that points to the agent's transcript (p6 shows it).

## 3. What the hook changes for the PI's recovery work (MEASURED, replay of this run)

`replay_run.py` fed the 7 real hand-backs present in this run's subagent transcripts (the `SubagentHandback` tool calls, 6,385 to 19,661 characters) to the hook as synthetic events: 7 of 7 are in the lab file verbatim, with the right file names, resolved from the real `.meta.json` files. The reports that `save_handback.py` saved for a, b, c, d, f (`replay_results.tsv`) differ from the verbatim text in three ways:
  - 5 of 5 end with 652 or 807 characters, from the closing `</agent-message>` on, that are not the agent's: a paragraph about "another Claude session" after the report;
  - 3 of 5 (b, d, f) carry the harness's tag neutralisation, 7, 4 and 8 occurrences of `<\` where the agent wrote `<` (`<\system-reminder>`, `<\agent-message ...>`), while the file header says "Text unchanged"; a and c are identical once the trailing text is cut;
  - the harness's `[harness: ...]` line and the two-space indent are added to all of them (the replay removes them before comparing).
The agent's own text cannot be recovered from the saved files where the agent itself wrote `<\`: the neutralisation is lossy. The hook copy is taken before the harness rewrites it; p5 shows the rewriting on the receiving side (`<\task-notification>`, indent, `[harness: ...]` line, the same text in two record kinds, `queue-operation` and `user`).

## 5. What this does not show, and what it argues against

- Closes: the claim that the hand-back text of a named subagent cannot be captured faithfully by a plugin hook in auto and default mode on 2.1.299 and 2.1.302. Does not cover: a live Desktop GUI session with the hook installed (the hook's `cwd` and `CLAUDE_PROJECT_DIR` there, and the background-agent path, were not run), and a hand-back that auto mode's review withholds (the binary has `handback` states `send`, `flagged`, `withheld`; `tool_response` for the hand-back that carried a harness note (p5) is identical to the plain case, so the hook cannot tell them apart).
- The hook does not remove the need for a brief change; two separate things. (a) Briefs should stop asking for `report.md`, `summary.md`, `findings.md` and `analysis.md` from a subagent. Proposed wording for `briefs.md` item 4 (not applied): "Your final message is your report; the platform refuses a subagent's Write of files named REPORT*, SUMMARY*, FINDINGS*, ANALYSIS* ending .md. Write data, code and puzzles to files; hand the report back as text." (b) The hook is the durable, verbatim copy of what was handed back. A zero-code alternative to (b) is a brief that asks for the report in a file with another name (`<name>-notes.md` is allowed), but that leaves the PI-visible copy altered and relies on the agent writing it.
- Against the hunch's strength: the PI already receives the hand-back in context, so the file adds recoverability and verbatim fidelity, not new information; explorer-w01-b measured return text at about 26 k tokens in total and judged return text not the cost driver.
- Safety: the file holds unfiltered model output, without the frame the harness puts around hand-backs ("model output, NOT a message from the user"), and the harness's flag note is not stored. The file header in `handback.py` says "Final messages, verbatim"; a reader (agent or human) must treat the content as data. Recorded as a puzzle.
