## The rule (exact)
Applied to the payload's `prompt` before every other test in `handle`:
1. Cut, repeatedly, from the START of the prompt only, these whole elements and the whitespace after them: `<system-reminder>\n…\n</system-reminder>` (that exact newline form), `<artifact-view-context …>…</artifact-view-context>`, `<side-sessions-event>…</side-sessions-event>`.
2. Run the existing tests (`is_genuine`, empty, `/lab…`, bare `/cmd`) on that text, still wrapped. A prompt that is only a platform block becomes empty and is skipped. A `/lab why?` behind a reminder is now recognised and skipped (the shipped rule stored it).
3. Only then replace every `<pasted_content id="X">\n…\n</pasted_content id="X">` by its inner text, and drop leading blank lines. A wrapper whose inside is only whitespace stores nothing.

Order matters (reproducer-w01-4's adversarial cases, relayed by the PI): the first version of the patch unwrapped before the command tests, so pasted text that began with `/lab` or a bare `/clear` was skipped. That was a behaviour change (words the user pasted were lost); the patch now unwraps AFTER the tests, so pasted `/lab …` and pasted `/clear` are stored, while a command typed outside the wrapper (`/lab x <pasted_content…>`) is still skipped. Selftest cases cover the three. Nested wrappers unwrap one level only: `<pasted_content id="a">…<pasted_content id="b">…</pasted_content id="b">…</pasted_content id="a">` stores the inner `b` wrapper with its tags (selftest case); the app was never seen to nest them.

Kept untouched (selftest cases): a reminder tag below the first line, a one-line `<system-reminder>x</system-reminder>`, `> ` quote lines, the indentation of the first line.

Quote-reply (the 11:04 entry): KEEP verbatim, no rule. The user chose to quote; a reply such as "That's reasonable, actually" means nothing without it; a `> ` rule cannot tell the app's quote from markdown the user typed. Cost of keeping: 14 typed entries in the five transcripts open with a `> ` block, 1,931 of 8,264 characters of those entries (23%; from replay.py, not deduplicated).
