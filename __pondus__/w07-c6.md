Tool fit: Rust for B (the protocol's binary), Python for the replay and session drivers (JSON, subprocess), C for the spawn bench (explorer-w07-a's driver extended with stdin from a file).

**What B is.** A std-only crate `rust/` (no dependencies, `Cargo.lock` lists one package; `#![forbid(unsafe_code)]`, `cargo clippy --offline` clean) with one binary `murmuration` and one subcommand `guard`; `budget` and `handback` would be further subcommands (not built). `guard` is a port of `scripts/permission_guard.py`, over code points because a Python `str` read from JSON can hold a lone surrogate; the regular expressions are written out by hand, the Unicode classes (`\s`, `\w`, `\d`) come from range tables that `rust/gen_tables.py` generates from Python 3.12.12's own `str.isspace/isalnum/isdecimal`, the JSON reader copies `json.loads` (NaN, duplicate keys, lone surrogates, 4,300-digit ints, depth 9,998), the failure names are Python's (`JSONDecodeError`, `AttributeError`, `TypeError`...). A panic in the decision becomes a deny. Binaries for the two darwin targets are committed under `bin/<target>/`; no other target built; no download. `scripts/install_binary.py` (SessionStart, exec form) copies `bin/<target>/murmuration` to `${CLAUDE_PLUGIN_DATA}/bin/murmuration` when absent or different (sha256, atomic), writes a `#!/bin/sh` launcher for `permission_guard.py` when no binary fits, and on any error exits 1 with a message on stderr. The 32 guard rows are `"command": "${CLAUDE_PLUGIN_DATA}/bin/murmuration", "args": ["guard"], "timeout": 20, "onFailure": "block"`. `scripts/check_guard_equal.py` is the replay; `scripts/git-hooks/pre-commit` and `.github/workflows/guard-binaries.yml` are files for the maintainer, not installed or pushed.

## What is shown, in the three units
- CPU: 16.0 ms less per guard start (g3, 600 of 600 pairs): shown for every Bash call and every matched Write/Edit call, in either permission mode.
- Start (spawn to exit of the guard process, outside the platform): 15.9 ms less (g3), reaching the one-exec floor.
- Wall, in the platform: the guard's recorded hook duration is 23.5 ms lower (g4, default mode). In auto mode the PreToolUse hook runs beside the classifier (explorer-w07-g: 642 against 631 ms to dispatch), so the call's wall saving there is about zero and only the CPU saving stands; on the Write/Edit rows and in default mode the wall saving is what g4 shows. A's rows are in exec form (P3's form); against today's string form the saving is larger (S-w07-author-w07-5-6).

## What this closes
It closes the question whether the permission guard can be one Rust binary, selected per platform at session start with no shell and a Python fallback, that keeps the Python guard's decisions on all string-valued events and its fail-closed behaviour, and what that costs to ship and saves per start on this machine. Outside that scope: a Linux or Windows binary, a marketplace-installed plugin's data folder, auto-mode wall time, and whether `budget` and `handback` can follow (they would carry their own tests).
