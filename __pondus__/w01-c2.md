## Results (all MEASURED unless marked)

R1. The two explorers are both right, for different permission modes. explorer-w01-a read sessions run in `auto`; explorer-w01-f ran `bypassPermissions`. The Desktop's launch flags (partial messages, omitted thinking display, effort high, stream-json input) do not matter; the permission mode does. Set `ablation`, one flag at a time from a plain run: each flag alone leaves the transcript exact; only `--permission-mode auto` makes it truncated, on both binaries.

R2. Final-file exactness of output tokens, by cell (`final_stats.txt`, `summary.txt`; "inexact" = transcript sum minus `modelUsage` differs):

| binary | mode | cells | output inexact | input, cache-read, cache-write inexact |
|:--|:--|--:|--:|--:|
| 2.1.299 | auto | 13 | 13 | 0 |
| 2.1.302 | auto | 13 | 13 | 0 |
| 2.1.299 | plan | 5 | 5 | 0 |
| 2.1.302 | plan | 5 | 5 | 0 |
| 2.1.299 | bypass, default, acceptEdits, dontAsk | 78 | 2 | 0 |
| 2.1.302 | bypass, default, acceptEdits, dontAsk | 78 | 2 | 0 |

In the 4 inexact non-auto, non-plan cells the cell type is always background subagent, short final message, thinking off; of 22 such cells 4 were inexact (0 of 20 background long with thinking on, 0 of 20 foreground short thinking off, 0 of 20 background long thinking off). `default`, `acceptEdits`, `dontAsk` have one cell each per binary (all exact), so those three modes are barely sampled. Thinking on/off, foreground/background and length do not matter in `auto`: 26 of 26 cells inexact over all combinations tested. Version (2.1.299 vs 2.1.302) does not matter anywhere in the data.

R3. What truncated looks like: in `auto` every request of the subagent file has `stop_reason: null` and `output_tokens` 2 to 20 in its last record; the long essay is the input of the `SubagentHandback` tool call (present in `auto`), so the largest request is the one that is truncated. In `plan` and the rare non-auto case one request has `stop_reason: null` while the others carry the final value. Sums of all records over-count (several records per request, one per content block); the first record per request under-counts even when the file is final (non-auto: 358 vs 2,223 in the first cell). Right method: last record per `requestId`.

R4. A validity test holds on all 192 cells without exception: "every request's last record in the file has a non-null `stop_reason`" is true exactly when the output sum equals `modelUsage` (152 of 152 true, 40 of 40 false). CHECKED on the real transcripts with the same test (`real_files.py`): 444 of 505 genesis, 813 of 907 design, 629 of 680 this-run subagent requests have a null last record, and 0 of 55 agent files are all final; all three sessions ran with `permissionMode` `auto`; main-thread files have 0 null requests. Input, cache-read and cache-write sums equal `modelUsage` in all 192 cells and in the cells of every mode.

R5. Sources of exact per-run output when the file is truncated (4 cells with OTel, 2 per binary, one `auto` and one `bypassPermissions` each):
- OpenTelemetry `api_request` events (env `CLAUDE_CODE_ENABLE_TELEMETRY=1`, OTLP/HTTP-JSON to a local receiver, set at process start): per request input, output, cache-read, cache-creation, cost and `request_id`, `agent.name` (the type, not the instance). Sum equals `modelUsage` for all four tokens and `total_cost_usd` to the last digit in all 4 cells, `auto` included (otel subagent output 1,864 vs transcript 8 in the 2.1.302 `auto` cell). The user must set the variables outside the plugin (explorer-w01-f run6, CITED to its report); whether the Desktop honours them is untested.
- `--forward-subagent-text` stream messages: carry `request_id` and `agent_id` but the same truncated usage (31 to 32 output tokens in total in `auto`); not a source.
- `result.modelUsage` / `cost-state`: exact per model in every cell; per subagent only as (total minus main-thread sum) when one subagent runs, or per model for all subagents together. `cost-state` is written at session end only (CITED, explorer-w01-a).
- Content-length estimate (ESTIMATE): tokens per character calibrated on the Opus main thread and applied to genesis Sonnet subagent content gave 454,849 against `cost-state` 1,075,475 (ratio 0.42; Fable 26,345 against 36,807), so it is not usable. `estimate_out.py`.
- `subagent_tokens` in the Agent result and `PostToolUse(Agent).totalTokens` are the last request's footprint (explorer-w01-f, CITED), not spend; not re-measured here.

R6. SubagentStop hook. The hook input carries `agent_transcript_path` and `permission_mode` (seen as `auto` in the `auto` cells), so the hook can know when the file is untrustworthy. The hook sees the same file as later: in `auto`/`plan` it is truncated at hook time and at the end (polling for 4 s never settled, 14 of 14 polled cells). In non-auto cells the hook saw the file before the last request's final usage was written in 17 of 156 cells (11%; 7 of 78 on 2.1.299, 10 of 78 on 2.1.302), output then 85 to 394 against 1,500 to 1,800 true. Polling the same file settled in about 0.056 s in the 4 polled cases of this kind (2.1.302, foreground, long); in 3 other polled cases the file never settled (the permanent rare truncation of R2). So a hook that reads the file at SubagentStop gets the final values in about 89% of non-auto runs, start-of-stream values in `auto`, and can detect which with the R4 test.
