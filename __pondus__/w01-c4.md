## The rule (exact)

Applied to the payload's `prompt` before every other test:

1. Cut, repeatedly, from the START of the prompt only, these whole elements and the whitespace after them:
   `<system-reminder>\n…\n</system-reminder>` (that exact newline form), `<artifact-view-context …>…</artifact-view-context>`, `<side-sessions-event>…</side-sessions-event>`.
2. Replace every `<pasted_content id="X">\n…\n</pasted_content id="X">` by its inner text.
3. Drop leading blank lines. Nothing else is touched: a reminder tag further down, a one-line `<system-reminder>x</system-reminder>`, quote lines starting with `> `, indentation of the first line are kept (selftest cases).
4. Then the existing tests (`is_genuine`, empty, `/lab…`, bare `/cmd`) run on the cleaned text. A prompt that is only a platform block becomes empty and is skipped. A `/lab why?` hidden behind a reminder is now recognised and skipped (before, it was stored).

Quote-reply (the 11:04 entry): KEEP verbatim; the proposal has no rule for it. Reasons: the user chose to quote, and replies such as "That's reasonable, actually" mean nothing without it; a `> ` rule cannot tell the app's quote from markdown the user typed. Cost of keeping: in the five transcripts 14 typed entries open with a `> ` block, 1,931 of 8,264 characters of those entries (23%), about 2 k characters in all.

Root: `lab_root(cwd)` = the nearest directory with `__statera__/` from the payload `cwd` upward, stopping at the first directory that has a `.git` (file or folder, so a linked worktree is a boundary); else CLAUDE_PROJECT_DIR if it has a `__statera__/`; else nothing. Same helper used by `resume_brief.py` (the shipped one has the identical `CLAUDE_PROJECT_DIR or cwd` line, so a resumed worktree session gets the other checkout's wave note). Not touched: `lab_status.py`, `lab_init.py` (no payload; they run from the Bash tool, whose environment in this agent's shell has no CLAUDE_PROJECT_DIR, so they use the shell's cwd).

### 3. Capture at Stop (MEASURED; trade-off)

- A prompt sent while a turn runs fires UserPromptSubmit with the SAME `prompt_id` as the turn, Stop fires once, and the transcript stores that prompt as `attachment.type = queued_command`, not as a `user` record (case7). Reading `user` records alone misses these: 13 of the 87 typed prompts (15%) in the five transcripts.
- `origin.kind == "human"` exists in Desktop transcripts; in headless stream-json input `origin` is null (the same null as the 9 platform notices). - Cost of Stop: about 60 more lines, five undocumented record fields (`promptId`, `origin.kind`, `isMeta`, `queued_command`, `commandMode`), a cursor to avoid double capture, entries dated at turn end (the record's own timestamp can fix that), nothing written until the turn ends. Interrupt behaviour was not tested.
Recommendation: stay at UserPromptSubmit. If scheduled prompts matter, drop them by a second rule (below), do not move the capture.
