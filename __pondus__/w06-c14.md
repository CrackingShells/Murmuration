# w06-c14: Starting the permission guard as `python3 -S -I` (32 hook rows, command strings only) gives identical decisions and a lower start cost: median 65.2 ms against 71.9 ms per Bash call through `sh -c` (new faster in 58 of 60 alternating pairs, 12-core machine, load average 2.4)

label: MEASURED
scope: the 32 rows of `hooks/hooks.json` that start `scripts/permission_guard.py`, old = 6c826d3 (plain `python3`), new = 0ee7652 (`python3 -S -I`), on macOS with Python 3.12.12 (miniforge) and Claude Code 2.1.304; decisions are judged on the 121 registered cases, 4 malformed events, and the lab's 5,136 recorded Bash/Write/Edit calls. It does not cover another Python (a `python3` without a readable standard library, or one whose `-I` behaves differently), the guard's decision quality (unchanged and not re-examined; the holes of w06-c11, c12, c13 stand), nor the platform's own hook-start overhead (one live control run only).
evidence: hooks/hooks.json@0ee7652, scripts/permission_guard.py@0ee7652, __instrumenta__/w06c14_cmd_equal.py@0ee7652, __instrumenta__/w06c14_bench_guard.py@0ee7652, __instrumenta__/w06c14_live_failclosed.py@0ee7652, __instrumenta__/w06c13_decide_diff.py@5b43cc4, __instrumenta__/w06c13_v7_diff_two_guards.py@5b43cc4
method: experiment and offline check. The change (0ee7652): in `hooks/hooks.json` each of the 32 guard rows reads `python3 -S -I "${CLAUDE_PLUGIN_ROOT}/scripts/permission_guard.py"` (was `python3 "..."`); nothing else in that file moves. In `scripts/permission_guard.py` only the module docstring changes (puzzle S-w06-reproducer-w06-8-3: it said an ordinary tool call starts no process; the Bash row has had no `if` since v3, the Write/Edit/NotebookEdit rows still have it; it now also states the lean start). No code line changes, so `decide()` is byte-identical in logic. Why `-S -I` is safe: the guard imports only `json os re shlex sys` (and `tempfile` inside `--selftest`), all standard library, which `-S` (no `site`) does not hide; it imports no sibling file, which `-I` (no script directory on `sys.path`) would hide; `MURMURATION_GUARD_LOG` is read with `os.environ.get`, and `-I` ignores only `PYTHON*` variables, so the log variable is unaffected (shown live below: one log line under `-I`). Import laziness was examined and not done: `python3 -S -I -X importtime scripts/permission_guard.py` shows the whole import cost is about 5 ms, almost all of it `json` and `re` (needed by the module's own regexes on every start); a lazy `shlex` or `json` would save under 0.3 ms. Compiling the 415-line script at each start costs 2.2 ms (a bytecode-cached `run_hook.py` start would save at most that); not done, as the brief asks for command strings only.

6. MEASURED, start time: `python3 -I __instrumenta__/w06c14_bench_guard.py 6c826d3 60` (quick: `... 6c826d3 6`, about 10 seconds). It runs the Bash-row command string of each tree through `sh -c`, one ordinary event on stdin, 60 alternating pairs (order flips each round), plus `sh -c :` and `python3 -S -I -c pass` as floors in the same loop, 2 warm-up starts per arm. Result: old median 71.9 ms (p10 70.3, p90 75.4); new median 65.2 ms (p10 63.3, p90 72.3); `sh -c :` 30.8; `python3 -S -I -c pass` 53.2. Old minus new per pair: median 6.6 ms (p10 2.3, p90 9.7); new faster in 58 of 60 pairs. Load average (1, 5, 15 min) 2.42, 2.27, 3.46 before and 2.33, 2.26, 3.43 after, 12 cores, a mostly idle machine (another lab session may have been among the load). The first quick run (n=6) gave 73.4 against 65.5. These are start times of the command through `sh`, not the debug-file `finished with status 0 (N ms)` of 131 to 150 ms that reproducer-w06-8 saw under a live session; the saving (about 7 ms, 9 percent of the guard's own start) is the part this change can claim, and the platform's share of the 131 to 150 ms is untouched.
Landing rule given by the PI: identical decisions on every case and a lower median start. Both hold (0 of 660 end-to-end differences; median 65.2 against 71.9 ms). Size: 32 command strings, a docstring, no code line. Cost: about 5 minutes of machine time for all of it; the live pair about 21 seconds of haiku. Seeds: the sample of 400 recorded calls uses `random.Random(0)`; the bench has none; haiku at its default temperature.
