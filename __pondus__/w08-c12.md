- **The rule that makes it hold.** A start that no answer has tied to a dispatch takes a dispatch record only when it is the only fresh one of its type (it is then this agent's: its own record is in play, and no other agent's can be). When several are fresh it removes none, logs the figures as unknown when they differ, and says `name_unconfirmed` with all their names as candidates when the names differ (equal names stay confirmed). A record leaves only when its own answer names the agent that owns it (moved to `names/<id>.json` when the agent has not started; removed, with one `named` line, when it has) or when it expires. This repairs the defect reproducer-w08-5 found: a late answer used to move a record out of the pool while an earlier start had taken another one.
