## Task 2 (CONJECTURE): capture the user's dialog answers with a `PostToolUse` hook, matcher `AskUserQuestion`
Why: the answers arrive as a tool result, so `UserPromptSubmit` never fires (S-w02-research-pi-1); this run's answers (transcript line 1473, 03:26:57Z = 12:26 JST; the question call is at line 1472, 03:05:10Z) are in no `user_words.md`.

Facts, MEASURED from the transcripts (read only): the five transcripts hold 5 answered dialogs (4 in 2947f9dc, 1 here), 10 questions, 12 answer texts. Each tool result record has the model-facing string and a structured `toolUseResult` = `{questions, answers}`, `answers` mapping each question text to a string (single-select or typed text) or a list of strings (multi-select; a typed "Other" in a multi-select is a list of one). The string comes in two wordings (`Your questions have been answered: … You can now continue with these answers in mind.` when every answer is an option label, 2 of 5 dialogs and the headless single-select run; `The user answered: … Read the answers carefully …` when some answer is typed text, 3 of 5 dialogs and the headless multi-select run), joins a list with a bare comma and quotes each pair as `"q"="a"`: so the string is not a verbatim record when an item has a comma, while `toolUseResult` is. No declined or errored dialog occurs in the five transcripts.

Facts, MEASURED headless (Claude Code 2.1.302, haiku, `e2e_headless.py`, raw output in the PI's scratchpad, USD 0.049 over 7 short runs): `claude -p` has no `AskUserQuestion` by default (w01-c6), but it appears with `--tools AskUserQuestion --permission-prompt-tool stdio --permission-prompts host`, which is the SDK-host protocol; the tool then raises a `control_request` (`can_use_tool`, `requires_user_interaction: true`) that a host answers with `behavior: allow` and `updatedInput.answers`. With a PostToolUse hook on the matcher: the hook fires; its payload has `tool_name`, `tool_input` (questions plus `answers`), `tool_response` = the same `{questions, answers}` as the transcript's `toolUseResult` (lists preserved, a comma-and-Japanese item intact), `tool_use_id`, `duration_ms`, `cwd`, `session_id`, `transcript_path`. A declined dialog (`behavior: deny`) fires PreToolUse only; no PostToolUse and no PostToolUseFailure.

The prototype `ask_capture.py` (not in `hooks/`; registration in `hooks_addition.json`) reads `tool_response.answers` (else `tool_input.answers`, else a string `tool_response` as is), and appends through `user_words.append_words`, so it lands where `user_words.py` lands (same `project_root`), under the dated heading:
```
(answer in the question dialog)
Q: <question verbatim>
A: <answer verbatim>        (a list answer: "A:" then one "- item" line each)
```
Checks: its selftest passes; replaying the 5 real dialogs through it as payloads stores all 12 answer texts verbatim (12 of 12; `replay_asks_output.txt`); the headless end-to-end run wrote the single-select and the multi-select entries as above and nothing for the declined dialog (`e2e_headless_output.txt`). Cost: 142 lines of script (82 up to the selftest), one 10-line hook entry, no new platform field beyond `tool_response`.

Why it stays CONJECTURE: no Desktop payload was ever dumped. The Desktop's own transcript record has the same `{questions, answers}` shape as the headless `tool_response`, which makes the same payload likely, but whether the Desktop fires `PostToolUse` for a dialog answered in its UI, and whether a plugin hook with that matcher is loaded for it, is untested. A one-minute Desktop test settles it: a throwaway lab with `.claude/settings.local.json` holding the `hooks_addition.json` entry (absolute path to `ask_capture.py`), a new Desktop session there, ask the agent to call `AskUserQuestion`, answer, read `__statera__/user_words.md`. Not covered: whether a subagent's dialog fires the hook in the parent's settings; typed "Other" text versus an option label (both arrive as the same kind of string in `answers`; the hook could tell them apart by comparing with the option labels in `questions`, which the prototype does not do).
