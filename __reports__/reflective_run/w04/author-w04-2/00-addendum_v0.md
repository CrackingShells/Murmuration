# Addendum to the wave-4 protocol (E1, E2): exploratory arms, written before they run

Written by author-w04-2 on 2026-10-20, after the pilots and the 6 pre-registered E1 runs and before the C runs of E2 and the exploratory runs. It changes no metric and no rule of `00-experiment_protocol_v0.md`; the decisions of E1 and E2 are taken on the pre-registered runs only.

Why. The pilots (pilot-a, pilot-c, N = 90 files, budget USD 0.30, brief names the findings report at the convention path as the deliverable) showed that an explorer whose brief names the report writes it before it hands back: 0 deny lines in the pilot with notes on, and none in the 3 A runs of E1 [source: `derived/` tables of this folder]. The wave-3 denies came from briefs that said "write the list in your hand-back" and from tasks of 90 to 200 files. The pre-registered E1 task therefore tests the line on briefs that already name the report; the wave-3 shape (list in the hand-back, work far above the budget) is not covered by it.

Exploratory runs (not decisions; labelled EXPLORATORY, n = 3 per arm, MEASURED at that n):
- X: brief as in wave 3: `Your deliverable is the complete list, one line per file ... Write it in your hand-back.`; N = 150 files (about 1.6 to 2 times the budget), budget USD 0.30, 20 min; seeds 20261031 to 20261033 (paired across arms).
- XA the branch unchanged (arm A export), XB with the line (arm B export), XC every budget.py output off (arm C export, as in E2).
- The same metrics (m1 to m5, n1 to n5) and the E1 and E2 rules are applied to X as a reading aid, and reported as "exploratory reading", never as the decision.
- Cost cap: the sum of all runs of the two claims stays at or under USD 12; if the pre-registered runs use more than expected, XC is dropped first.
